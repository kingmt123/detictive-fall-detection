# Unified Video Source and Pose Cache Implementation Plan

> **For Hermes:** Implement with strict RED→GREEN tracer bullets; keep GPU work serialized on the mainline.

**Goal:** Build a deterministic, resumable pose-extraction layer that reads local MP4 and OF-Syn `tar://archive!/member` sources through one contract, writes validated atomic NPZ caches, and proves the path on 2 URFD + 2 OF-Syn validation clips without touching test.

**Architecture:** `VideoSourceResolver` owns open tar handles and D:-resident temporary materializations. `PoseExtractor` owns one YOLO pose model and emits a dense per-frame/per-observation sequence. `pose_cache` validates schema/signatures and atomically replaces one NPZ per clip. The CLI performs manifest validation and cache probing before inference; training later consumes only NPZ, never YOLO.

**Tech Stack:** Python 3.11, stdlib `tarfile/hashlib/tempfile`, OpenCV, NumPy NPZ, Ultralytics YOLO, pytest, Ruff.

## 1. Decisions that are frozen before coding

### 1.1 Scope boundaries

- Gate 2A does **not** train TCN, tune thresholds, add augmentation, read test, run 12,000 clips, add multiprocessing, or refactor the working inference engine. Gate 2B must add one minimal evaluator/engine tar-source tracer before the OF-Syn rule baseline; it must not rewrite rule/event logic.
- First vertical slice is source URI → local decodable path → pose arrays → atomic NPZ → validated resume.
- All tar temporary files live under explicit `runs/tmp/video-source/` on D:. Never use Windows system Temp: C: has only ~5.8GB free.
- One process and one GPU worker only. Optimize concurrency only after measured 20-clip canary throughput.

### 1.2 Unified source contract

Create `pipeline/video_source.py`:

- `parse_video_source(source: str | Path) -> LocalSource | TarSource`
- `VideoSourceResolver(temp_root: Path)` as a context manager; it caches one open `tarfile.TarFile` per archive for the batch.
- `resolver.probe(source) -> SourceIdentity` performs cheap stale-cache checks:
  - local: canonical path, file size, `mtime_ns`;
  - tar: canonical archive path, archive size/`mtime_ns`, exact member name, member size/mtime/offset.
- `resolver.materialize(source)` yields `MaterializedVideo(local_path, identity, content_sha256)`:
  - local MP4 is copied to an immutable file under the explicit temp root while hashing, so the decoder consumes the exact bytes named by the SHA;
  - tar member streams to a uniquely named file under the explicit D: temp root while computing SHA-256;
  - temporary member is removed in `finally`, including decode/model failures.
- A candidate resume first passes cheap identity/schema/signature checks, then `content_sha256()` streams the exact local/tar bytes without materializing a tar member; preserved size/mtime cannot hide changed bytes.
- Parse only the exact `tar://<archive>!/<member>` form. Preserve `./` member prefixes. Reject missing delimiter, missing archive/member, non-file tar members and duplicate/ambiguous forms.

### 1.3 Pose cache schema v1

Create `pipeline/pose_cache.py`. Each NPZ uses numeric/unicode arrays only and must load with `allow_pickle=False`:

| Key | dtype / shape | Meaning |
|---|---|---|
| `cache_schema` | int64 scalar, value `1` | migration gate |
| `clip_id` | unicode scalar | manifest identity |
| `dataset`, `split` | unicode scalar | leakage audit |
| `source_identity_json` | unicode scalar | cheap resume fingerprint |
| `source_content_sha256` | 64-char unicode scalar | exact bytes used initially |
| `extractor_signature_json` | canonical unicode JSON scalar | model + code + crop/config signature |
| `fps` | float64 scalar | sanitized source FPS |
| `frame_indices` | int64 `[T]` | contiguous decoded frame indices |
| `timestamps` | float64 `[T]` | `frame_index / fps`, finite and monotonic |
| `keypoints` | float32 `[T,P,17,3]` | cropped-frame coordinates and confidence |
| `bboxes` | float32 `[T,P,4]` | xyxy in cropped-frame coordinates |
| `track_ids` | int64 `[T,P]` | `-1` for padding |
| `valid_mask` | bool `[T,P]` | true observations; rows sorted by track ID per frame |
| `frame_size` | int64 `[2]` | cropped height/width |

`P` is max simultaneous tracked observations in the clip. It may be zero. Track continuity is represented by `track_ids`, not by assuming a fixed column slot.

Cache path is derived from dataset/split plus SHA-256 of `clip_id`, never by treating clip IDs containing `/` as paths. Write to a sibling temporary file, flush + `fsync`, validate the temp NPZ, then `os.replace`. A corrupt/truncated cache, wrong schema, wrong identity/signature, illegal shape/dtype, NaN/Inf, non-monotonic timestamps or invalid padding is a cache miss/error and is never reported as success.

### 1.4 Extractor contract

Create `pipeline/pose_extractor.py`:

- one model instance per `PoseExtractor`;
- one `MultiPoseTracker` per clip;
- reuse existing `crop_frame`, `sanitize_fps` and tracker behavior rather than creating a second incompatible geometry convention;
- emit every decoded frame, including frames with no person (`valid_mask` all false);
- signature binds model SHA-256, complete relevant source code hashes, dependency versions, image size, confidence, device, crop mode and cache schema;
- no fall score, event aggregation or labels in this layer.

Create `tools/extract_keypoints.py`:

- required explicit `--manifest --dataset --split --cache-root --model`;
- `split=test` is rejected in Gate 2, with no override;
- validate manifest columns, explicit split and duplicate clip IDs before lazy model construction; labels are not consumed by pose extraction;
- support repeatable `--clip-id` selection for smoke and `--limit` for canary;
- probe valid matching NPZ first; `PoseExtractor` lazily instantiates YOLO only for the first miss and reuses it thereafter;
- print a stable machine-readable summary with selected/processed/resumed/rebuilt/failed, per-clip frame/person/cache/timing data, elapsed and processed clips/s;
- any failure makes the command non-zero; no zero-filled success cache.
