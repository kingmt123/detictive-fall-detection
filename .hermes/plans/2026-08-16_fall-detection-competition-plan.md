## 第一部分：赛题综合评估

### 1.1 评分结构拆解（决定开发资源分配）

| 评分项 | 权重 | 关键含义 | 应对策略 |
|---|---|---|---|
| 检测精度 MAP = (P@R90 + P@R95) / 2 | 50%（占竞赛得分） | **视频片段级**事件检测：TP=真跌倒被检出，FP=日常动作误报，FN=漏检。要求 R95 时仍有高精准率 → **高召回 + 强误报抑制**同等重要 | 时序语义判别 + 事件级后处理，而非单帧检测 |
| 模型参数量 | 25% | 基线 25 分（≤20M，fp32≤80MB），低于约束最多 +10 分，超过扣分，>40M 得 0 分 | 目标 **8~15M**，留出加分空间又保精度 |
| 推理耗时 | 25% | 基线 25 分（≤100ms/帧，云端 V100），低于约束最多 +10 分，>200ms 得 0 分 | 目标 **≤40ms**，轻量骨干 + 低算法输入分辨率 |
| 专家评分 | 赛题总分 30% | 新颖性、合理性、文档质量、与业界对比 | 方案文档 + 视频展示是另一战场 |

**结论**：这是一个"精度 × 轻量化 × 工程完整度"的三维优化问题。竞赛得分 70% + 专家 30%，意味着**不能只刷模型指标，材料质量同样决定名次**。

### 1.2 关键技术判断

1. **评测单位是"视频片段中的跌倒事件"，不是单帧框**。每段可能含一个或多个跌倒/生活场景。→ 必须做**时序聚合**：单帧检出 → 滑窗 → 事件合并 → 输出事件置信度（用于 P-R 曲线扫阈值）。
2. **R95 高精准率是难点**。坐下、弯腰、蹲下、躺卧休息与跌倒视觉相似，单帧外观检测必然误报爆炸。→ 核心创新点应放在**"跌倒 vs 相似日常动作"的语义判别**（时序动态特征：质心下坠速度、身体倾角变化率、姿态水平化持续时间）。
3. **长尾场景（微光/红外/遮挡/多视角）是加分与拉分点**。→ 数据增强（低照度模拟、红外灰度化+噪声、随机遮挡）+ 多源数据集混合训练是性价比最高的泛化手段。
4. **测试平台已改为云端 V100**（赛题补充说明）：**无需做海思/瑞芯微 NPU 转换**，省下 3~5 天部署适配工作量；但参数量/耗时约束仍是评分项，轻量化设计不能放松。
5. **红外支持是硬性要求**（"需要支持红外图像的跌倒检测"）：方案上采用**灰度/单通道兼容的输入设计** + 红外域增强，而非单独训练红外模型。

### 1.3 技术路线选型对比

| 路线 | 代表 | 参数量 | 时序语义 | 长尾泛化 | 16 天可行性 | 结论 |
|---|---|---|---|---|---|---|
| A. 单帧 YOLO 检测（fall/not-fall 两分类框） | LFD-YOLO、BMR-YOLO、YOLO-fall | 3~8M | 弱，靠后处理 | 中 | ★★★★★ | **作为基线与兜底** |
| B. 3D-CNN / Video Transformer 端到端 | VideoMAE、X3D | 大/时延高 | 强 | 中 | ★★ | 超时延/参数预算，放弃 |
| C. **检测+轻量姿态+时序分类（骨架）** | YOLO11-pose + TCN | 3~13M | 强 | **好**（骨架对光照/红外/纹理天然鲁棒） | ★★★★ | **主推方案** |
| D. 纯规则（bbox 长宽比+下坠速度） | 传统方法 | ~0 | 中 | 差 | ★★★★★ | 作为后处理组件融入 C |

**推荐：C 为主干 + A 为并行冗余通道 + D 为事件级裁决后处理**。三通道融合输出事件置信度：
- 通道 A（外观）：YOLO11n 检测 fallen/person，提供外观置信度；
- 通道 C（骨架时序）：YOLO11s-pose（9.9M，主推）或 YOLO11n-pose（2.9M，备选）提 17 关键点 → 轻量 TCN（~0.3M，GRU 作对照）做滑窗（16 帧）时序分类；
- 通道 D（物理规则）：bbox 长宽比突变、髋部质心垂向速度、身体主轴倾角、倒地后静止时长 → 事件确认/否决。

总参数：主推 ≈ YOLO11n(2.6M) + YOLO11s-pose(9.9M) + TCN(0.3M) ≈ **12.8M**；备选（n-pose）≈ **5.8M**。**两个版本都训，按加权得分择优提交**。
**调研关键结论（docs/research/lightweight_options.md）**：V100 上视觉部分 FP16 仅 2~5ms，时延指标基本"白送"，真正瓶颈在 Python 前后处理；压缩手段优先级 = MGD 特征蒸馏（教师 YOLO11m-pose 自训）> FP16 > RepConv 重参数化 > 剪枝；申报保持 fp32 权重（≤80MB 口径），INT8 默认不用（小目标掉点风险）。

### 1.4 风险清单

| 风险 | 等级 | 缓解 |
|---|---|---|

## 第二部分：总体架构设计

```
1080P 视频流
   │  (抽帧/降采样至算法输入 640×640，帧率 15~25fps)
   ▼
┌─────────────────────────────────────────────┐
│ 通道A: YOLO11n 外观检测 (person / fallen)      │──→ 外观置信度 s_a(t)
│ 通道B: YOLO11-pose 17关键点                    │──→ 骨架序列 K(t)
│         │                                    │
│         ▼                                    │
│   轻量时序网络 TCN/GRU (滑窗 T=16~32帧)        │──→ 时序置信度 s_b(t)
│         │                                    │
│         ▼                                    │
│   物理规则引擎:                               │──→ 规则置信度 s_c(t)
│   · bbox 长宽比 w/h 突变                      │
│   · 髋部质心垂向速度 > v_th                   │
│   · 身体主轴与水平夹角 < θ_th                 │
│   · 倒地静止持续 > τ_th                       │
└─────────────────────────────────────────────┘
   ▼
事件聚合器（时序平滑 + 滞回阈值 + NMS-on-timeline）
   ▼
跌倒事件输出: {t_start, t_end, confidence}  → 告警 / 评测
```

**输入设计**：RGB 与红外统一为 3 通道（红外灰度复制 3 通道），训练时随机灰度化，使单模型兼容双模态。
**隐私卖点（专家评分素材）**：全端侧闭环、可选只上传骨架/事件不上传视频。

## 第四部分：AI Agent 使用策略（本计划核心）

### 4.1 Agent 分工矩阵

| Agent 角色 | 调用方式 | 任务示例 | 并行度 |
|---|---|---|---|
| 调研 Agent ×3 | `delegate_task` 并行 | ① OmniFall 等数据集格式/许可/下载链路盘点；② LFD-YOLO/BMR-YOLO/YOLO-fall + 2024-25 跌倒检测 SOTA 方法精读；③ 轻量化技术（RepGhost/蒸馏/剪枝）选型报告 | 3 路并行，D1 完成 |
| 数据工程 Agent | `delegate_task` | 各数据集 → 统一格式的转换脚本（每数据集一个子任务），含可视化抽查 | 按数据集并行 |
| 评测 Agent | 直接实现（关键路径，不外包） | metrics.py / benchmark.py，先写 toy 测试 | — |
| 训练 Agent | `terminal` 后台 + `notify_on_complete` | 每次训练后台跑，完成自动通知，主线程继续写代码 | 训练与开发重叠 |
| 误报分析 Agent | `execute_code` | FP 片段自动导出、聚类、生成归因报告 | — |
| 文档/视频 Agent ×2 | `delegate_task` 并行 | 项目文档初稿（喂消融数据）+ 视频脚本/分镜；demo 录屏剪辑 | D13 起 2 路并行 |

### 4.2 工作纪律

1. **关键路径不外包**：评测脚本、融合策略、最终调参由主线亲自做——指标定义错一切白搭。
2. **子 Agent 上下文自包含**：每个 `delegate_task` 必须带：目标、相关文件绝对路径、数据格式约定、验收标准（要返回可验证产物：文件路径/指标数字）。
3. **自报告不可信**：子 Agent 声称"已完成"后，主线必须亲自验证（读文件/跑脚本/看数字）再合并。
4. **训练全部后台化**：`terminal(background=true, notify_on_complete=true)`，绝不让 GPU 空闲等待、也不让主线程空等训练。
5. **方法论沉淀**：数据集转换踩坑、增强配方、调参结论用 `hindsight_retain` 记录（只记可复用方法论，不记临时数据）。
